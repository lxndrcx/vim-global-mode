1. INTRODUCTION                                   *global-mode-introduction*

There is one mode, and everybody is in it. Connect to a global mode server and
your modal state is no longer yours: when anyone connected presses `i`, every
editor on that server enters insert mode.

This is a joke plugin. It works exactly as described.

Requires Neovim 0.10 or newer. Pure Lua, no dependencies.

==============================================================================
2. SETUP                                                 *global-mode-setup*

>lua
    require("global-mode").setup({
      host = "127.0.0.1",
      port = 7777,
      user = vim.env.USER,
    })
<
The server is a separate project, written in Ada and verified with SPARK:

    https://github.com/lxndrcx/vim-global-mode-server-ada

Build and run it with: >

    git clone https://github.com/lxndrcx/vim-global-mode-server-ada
    cd vim-global-mode-server-ada
    gprbuild -P global_mode.gpr
    ./bin/global_mode --verbose
<
Nothing in this plugin needs an Ada toolchain; it speaks to whatever server is
listening on the configured port. Transport is UDP, in fixed 84-byte frames.

==============================================================================
3. CONFIGURATION                                        *global-mode-config*

                                                    *global-mode-setup-opts*
host                    string (default "127.0.0.1")
                        Address of the global mode server. Must be a numeric
                        address: libuv does not resolve hostnames, so
                        "localhost" fails to connect and retries forever.

port                    number (default 7777)
                        UDP port the server listens on for editors.

user                    string (default $USER, then $USERNAME, then "anon")
                        The name shown to everyone else when you change the
                        mode. This is who gets blamed. Capped by the server at
                        64 characters.

auto_connect            boolean (default true)
                        Connect on startup. Set false to require an explicit
                        |:GlobalModeConnect|.

notify                  boolean (default true)
                        Announce connection and disconnection with
                        |vim.notify()|.

reconnect               table (default { min = 1000, max = 30000 })
                        Exponential backoff bounds in milliseconds. The delay
                        doubles from `min` on each failed attempt, capped at
                        `max`.

                                                       *:GlobalModeConnect*
:GlobalModeConnect      Connect to the server and submit to the global mode.

                                                    *:GlobalModeDisconnect*
:GlobalModeDisconnect   Disconnect and reclaim your own modal state.

                                                        *:GlobalModeStatus*

                        editors are connected.

                        Report connection state, the global mode, and the
                        roster of connected editors.

5. STATUSLINE                                       *global-mode-statusline*

For lualine: >lua
    sections = { lualine_x = { require("global-mode").lualine() } }
<
Or build your own from the pieces: >lua
    require("global-mode").statusline()  -- "INSERT · alex"
    require("global-mode").highlight()   -- "GlobalModeInsert"
<
                                                  *GlobalModeChanged*
A |User| autocmd fires on every change, so other statusline plugins can hook
redraws: >lua
    vim.api.nvim_create_autocmd("User", {
      pattern = "GlobalModeChanged",
      callback = function() ... end,
    })
<
                                                  *global-mode-highlights*
These highlight groups are defined, each linked to a sensible default:

    GlobalModeNormal        GlobalModeInsert        GlobalModeVisual
    GlobalModeReplace       GlobalModeCommand       GlobalModeTerminal

7. HOW IT WORKS                                      *global-mode-internals*

A |ModeChanged| autocmd reports your mode to the server, which records it as
the global mode and pushes it to every other editor. Those apply it with
|nvim_feedkeys()|, always prefixed with CTRL-\ CTRL-N — the one escape that
works from every mode, terminal mode included.

Three things stop one keypress becoming an infinite storm:

  1. The server never echoes a change back to whoever caused it.
  2. The client stays quiet about the |ModeChanged| events its own forced
     change produces. Note the plural: because every applied mode is fed as
     CTRL-\ CTRL-N followed by a mode key, applying one from a different
     non-normal mode passes through normal and fires two events, not one. The
     client therefore tracks a queue of expected modes, treats a transit
     through normal as its own, and expires an entry after half a second in
     case the keys never take effect.
  3. Re-reporting the mode already in force is a no-op on the server, and does
     not advance the sequence counter.

Reports are also coalesced: a change is held for 20 milliseconds, so a burst
becomes one datagram carrying the mode you ended on. Each report carries a
counter, and the server ignores any report that is not newer than the last it
honoured from that editor — without it, two reports sent a millisecond apart
and reordered in flight would leave everybody in the mode you had just left.
The counter restarts on every handshake, on both sides at once.

                                                       *global-mode-resync*
Separately, the server's heartbeat carries the authoritative mode every five
seconds, and a client that has drifted adopts it. This is the only resync the
protocol has: it announces changes and nothing else, so an editor that missed
one — a frame dropped from a full outbox, two editors changing mode in the same
instant, an apply refused by the rate limiter — would otherwise disagree with
everyone else permanently. A client already in the global mode does nothing.

An unanswered heartbeat also has a second job: the server drops a client after
two of them, so a dead connection is not held open indefinitely.

                                                   *global-mode-operator-pending*
Operator-pending mode is dropped before anything is scheduled. A |ModeChanged|
autocmd calling |vim.schedule()| could once re-trigger itself in a loop between
normal and operator-pending until it saturated a core (neovim issue #22263).
So pressing `d` or `y` does not affect anyone else: you can still operate on
text, you simply cannot inflict a half-finished operator on the room.

Terminal mode is received and displayed but never forced.

A circuit breaker caps applied changes at 20 per second. If it trips, a warning
is issued and applies pause briefly, so a bug degrades into a log line rather
than a hung editor.

                                                       *global-mode-security*
There is no authentication. Anyone who can reach the port can change the mode
for everyone connected. Do not expose it to the public internet.
